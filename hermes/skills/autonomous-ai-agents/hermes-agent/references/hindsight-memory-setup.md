# Hindsight Memory Provider: Local Embedded Mode

Hindsight is a long-term memory provider for Hermes Agent with knowledge graph, entity resolution, and multi-strategy retrieval.

## Prerequisites

The `hindsight` plugin is bundled with Hermes Agent — check with `hermes memory status`:

```
Plugin:    installed ✓
```

If not installed, verify the plugin directory exists at `~/.hermes/hermes-agent/plugins/memory/hindsight/` or reinstall.

## Configuration

### Step 1: Set the provider

```bash
hermes config set memory.provider hindsight
```

### Step 2: Choose a mode

Three modes available:

| Mode | Description | API Key Needed |
|------|-------------|----------------|
| `cloud` | Connects to Hindsight Cloud API | `HINDSIGHT_API_KEY` from ui.hindsight.vectorize.io |
| `local_embedded` | Hermes spins up a local daemon with embedded PostgreSQL | LLM API key for extraction/synthesis |
| `local_external` | Points at an existing self-hosted Hindsight instance | Optional |

### Local Embedded Setup (recommended for single-machine use)

Two-level config system:
- **Config file** (`~/.hermes/hindsight/config.json`) — read by the Hermes plugin every session
- **Profile env** (`~/.hindsight/profiles/hermes.env`) — generated by the plugin for the embedded daemon
- **Env vars** (`~/.hermes/.env`) — fallback for both

The plugin's `_load_config()` resolves in this order: `~/.hermes/hindsight/config.json` → `~/.hindsight/config.json` → env vars.

#### Full config.json (v0.6.1+ plugin)

```json
{
  "mode": "local_embedded",
  "llm_provider": "openai_compatible",
  "llm_model": "deepseek-v4-flash",
  "llm_base_url": "https://api.deepseek.com",
  "timeout": 120,
  "idle_timeout": 300,
  "api_url": "http://localhost:8888",
  "bank_id": "hermes",
  "recall_budget": "mid",
  "memory_mode": "hybrid",
  "recall_prefetch_method": "recall",
  "auto_recall": true,
  "auto_retain": true,
  "retain_every_n_turns": 1,
  "retain_async": true,
  "retain_context": "conversation between Hermes Agent and the User",
  "recall_max_tokens": 4096,
  "recall_max_input_chars": 800,
  "recall_tags_match": "any",
  "banks": {
    "hermes": {
      "bankId": "hermes",
      "budget": "mid",
      "enabled": true
    }
  }
}
```

#### Environment variables (append to `~/.hermes/.env` via terminal redirection)

```bash
echo "HINDSIGHT_MODE=local_embedded" >> ~/.hermes/.env
echo "HINDSIGHT_LLM_API_KEY=sk-your-key" >> ~/.hermes/.env
echo "HINDSIGHT_API_LLM_BASE_URL=https://api.deepseek.com" >> ~/.hermes/.env
echo "HINDSIGHT_API_LLM_PROVIDER=openai" >> ~/.hermes/.env   # NOT openai_compatible!
echo "HINDSIGHT_API_LLM_MODEL=deepseek-v4-flash" >> ~/.hermes/.env
echo "HINDSIGHT_API_LLM_API_KEY=sk-your-key" >> ~/.hermes/.env
```

**⚠️ Critical**: The embedded daemon requires `HINDSIGHT_API_LLM_PROVIDER=openai` (not `openai_compatible`). The Hermes plugin converts `openai_compatible` → `openai` automatically when writing the profile `.env`, but if you set the env var directly or use the `hindsight-api` CLI standalone, use `openai`.

## How It Works

- **Auto-start**: The daemon starts on first `hindsight_retain` / `hindsight_recall` call
- **Auto-stop**: Sleeps after 5 minutes of inactivity (configurable via `idle_timeout`)
- **Auto-recall**: Before each agent turn, Hindsight injects relevant past memories into context
- **Auto-retain**: After each turn, conversation is asynchronously stored with entity extraction
- **Logs**: `~/.hermes/logs/hindsight-embed.log` (daemon startup), `~/.hindsight/profiles/<profile>.log` (runtime)

## Available Tools

In `hybrid` and `tools` memory modes:

| Tool | Purpose |
|------|---------|
| `hindsight_retain` | Store information with auto entity extraction |
| `hindsight_recall` | Multi-strategy search (semantic + entity graph) |
| `hindsight_reflect` | Cross-memory synthesis (LLM-powered) |

## Memory Optimization for Low-RAM Environments

The hindsight embedded daemon loads embedding models (BAAI/bge-small-en-v1.5 + reranker) into memory, consuming **1-1.5 GB RSS** at runtime. This is the #1 cause of OOM (Out of Memory) kills on WSL systems with ~8GB RAM. The OOM killer terminates processes without warning — gateway logs show a clean last entry then silence (no traceback, no error).

### Key config knobs

| Setting | Default | Optimized | Impact |
|---------|---------|-----------|--------|
| `idle_timeout` | 300 (5 min) | **60** (1 min) | Daemon shuts down faster when idle, freeing 1GB+ |
| `retain_every_n_turns` | 1 (every turn) | **3** (every 3 turns) | 3x fewer LLM calls to daemon, less memory pressure |
| `auto_retain` | true | keep true | Still auto-saves, just less frequently |

### Apply

Edit `~/.hermes/hindsight/config.json`:

```json
{
  "idle_timeout": 60,
  "retain_every_n_turns": 3
}
```

Then kill the running daemon so it restarts with new config on next use:
```bash
kill $(pgrep -f hindsight-api) 2>/dev/null
```

### OOM Diagnosis

If the gateway crashes silently (last log entry is a routine message like `Agent cache idle sweep: evicted 1 agent(s)`, then nothing — no traceback, no error):

1. Check memory before restarting: `ps aux --sort=-%mem | head -5`
2. hindsight-api is almost always #1 (14-19% MEM, 1-1.5GB RSS)
3. Check for zombie hindsight-api processes: `ps aux | grep defunct`
4. If multiple gateway instances were spawned by `--replace` failures, memory doubles temporarily

**Quick fix when OOM strikes**: Kill hindsight daemon first (`kill -9 <pid>`), then restart gateway. The daemon auto-starts on next memory operation.

### Swap as safety net

On WSL2, add swap via `C:\Users\<user>\.wslconfig`:

```ini
[wsl2]
swap=4GB
```

Then `wsl --shutdown` from PowerShell and restart WSL.

## Known Issues
- **Config hot-reload**: memory provider changes require a new session (`/reset` in chat, or restart gateway). Config is read at session init.
- **`hermes memory setup` wizard may silently fail**: In some environments, the interactive wizard completes without prompting, leaving `provider: ''` unchanged. Workaround: bypass the wizard entirely and configure manually:
  1. `hermes config set memory.provider hindsight`
  2. Create `~/.hermes/hindsight/config.json` with full local_embedded config (see above)
  3. Set `HINDSIGHT_MODE=local_embedded`, `HINDSIGHT_LLM_API_KEY`, and `HINDSIGHT_API_LLM_BASE_URL` in `~/.hermes/.env`
  4. Verify with `hermes memory status` (should show `Provider: hindsight, Status: available ✓`)
- **Daemon startup delay**: The embedded daemon starts on first memory operation; allow 60-120s for database migrations + DeepSeek API initialization. If the daemon seems stuck, check `~/.hindsight/profiles/hermes.log`.
- **Domestic network (China)**: The daemon needs to load embedding models (BAAI/bge-small-en-v1.5, cross-encoder/ms-marco-MiniLM-L-6-v2) from HuggingFace. The plugin sets HF_HUB_OFFLINE=1 by default, which blocks model loading when the network is unreachable. Override in the generated profile env at `~/.hindsight/profiles/hermes.env`:

  ```
  HF_ENDPOINT=https://hf-mirror.com
  HF_HUB_OFFLINE=0
  TRANSFORMERS_OFFLINE=0
  ```

  If models aren't cached, force-download:
  ```
  HF_ENDPOINT=https://hf-mirror.com python3 -c "from sentence_transformers import SentenceTransformer; SentenceTransformer('BAAI/bge-small-en-v1.5'); SentenceTransformer('cross-encoder/ms-marco-MiniLM-L-6-v2')"
  ```
