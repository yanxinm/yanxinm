# 论文/专业文稿优化工作流

## 适用场景
用户在 `/mnt/e/百度云同步盘/工作台账/` 中有待发表的论文、申报材料等专业文稿，需要基于工作台账中的实际项目案例进行充实优化。

## 标准流程

### 1. 文档定位
- 工作台账目录下 `.docx` 文件数量大、嵌套深
- 用 `search_files` 按关键词搜索文件名（不用 `search_files target=content`，因为 .docx 是二进制格式，ripgrep 搜不到内容）
- 如文件名不精确匹配，尝试多个相关关键词组合

### 2. 文本提取
```python
from docx import Document
doc = Document('file.docx')
for i, para in enumerate(doc.paragraphs):
    print(f'[{i}] {para.text[:200]}')
```
- 先打印前200字符确认结构，再全量提取
- 保存为 `.md` 到 `~/.hermes/tmp/` 便于后续分析

### 3. 结构分析
- 识别章节层级（一、二、三 → 1.1/2.1 → (一)(二)）
- 梳理核心论点、案例引用、数据支撑点
- 找出可以充实的薄弱段落（案例单一、数据缺失、时间线不完整）

### 4. 案例素材搜集
- 在工作台账中按主题关键词搜索相关 `.docx` 文件名
- 优先抽取**策划方案**、**申报案例**、**请示报告**——这些文档含最丰富的一手项目细节
- 并行提取多个文件（用 python-docx 循环处理），大幅节省时间
- 关注文件时间线：不同版本（如 1229→0113）能揭示方案迭代脉络

### 5. 充实重写
- **案例具体化**：将"开展了系列活动"改为具体活动名称、时间、地点、参与方
- **时间线纵向化**：将单年案例扩展为多年脉络（如 2024→2025→2026），增强说服力
- **概念模型化**：将分散做法提炼为可复用的分析框架（如"四层窗花矩阵""四阶共创模型"）
- **数据权威化**：引用方案中的实际数据（曝光量、覆盖人次、参与高校名单）

### 6. 查重检测
- 用 `web_search` 搜索论文中的独创性短语组合，验证无重复
- 用户自有案例数据（策划方案中的活动名称、数据）天然低重复率
- 正式投稿前建议用知网 AMLC 或万方做正规检测

### 7. 输出
- 保存优化版为 `原文件名_优化版.docx`
- 用 `python-docx` 格式化：正文仿宋 16pt，一级标题黑体 16pt 加粗，首行缩进2字符，固定行距28磅
- 向用户提供改动对照表（新增要素清单、字数变化、结构调整说明）

## 注意事项
- .docx 文件不能用 ripgrep/`search_files target=content` 搜索内容，只能搜文件名
- 原始文件只读不写，优化版另存为新文件
- 论文风格不同于工作台账四类公文（报告/方案/请示/总结），不需要套用公文排版规范
- 案例素材必须来自用户真实项目文档，不编造

## 论文精简流程（期刊字数限制）

适用场景：已有一版充裕的论文，需要压缩到期刊要求的字数（如 3500 字）。

### 压缩比例选择
- 通常目标字数为原文 50% 左右时，需要进行结构性压缩而非简单删句
- 优先从"章节合并"入手，而非逐段删减

### 压缩手法（优先级从高到低）

**1. 取消子标题，改为自然段落群**
- 原文三节各有子标题（2.1/2.2/2.3），精简版合并为一章内的连续叙述
- 用"一方面……另一方面……"或时间线过渡替代子标题分段
- 节省的是标题行+独立段首的理论铺垫文字

**2. 删除最弱的子节，核心观点压缩为一句话嵌入相邻节**
- 找出全文最"薄"的子节（理论铺垫多、案例支撑少、可替代性强）
- 将其不可舍弃的核心信息（如"数字化数据库"）压缩为一句话，附在相邻章节末尾

**3. 合并案例，去重就精**
- 多个子节涉及同一个案例的不同角度 → 合并到一个段落
- 同类案例只保留最具代表性的细节，删除重复铺陈

**4. 启示章节从 N 条减为 N-1 或更少**
- 4条启示→3条，将最弱的一条的核心观点渗入其他条
- 每条从一个段落压缩为 2-3 句核心判断

**5. 删除理论铺垫和修饰语，保留案例和数据**
- "媒介环境学认为……""在新媒体时代……"等理论引述 → 删除
- "彻底打破""极大拓展""全方位提升"等程度修饰词 → 删除
- 具体案例名称、时间、数据（4000万、2000万）→ 全部保留

### 字数验证
- 每次改动后即时计算字符数
- 目标±5%以内即可（如 3500 字左右 → 3300-3700 均可）
- 用 python 去 markdown 标记后统计：`sum(1 for c in clean if c not in ' \n\t\r')`

### 输出规范
- 保存为 `原文件名_精简版.docx`
- 向用户出具精简对比表：字数变化、章节变化、主要删减手法、保留的核心要素

## 定稿对比学习模式

当用户修改了你生成的文稿后，要求"看下调整了哪些地方，以后同类型可以借鉴"时：

1. **逐段对比**两份文本（原始生成版 vs 用户定稿版），而非概述差异
2. **按结构/内容两级分析**：先标出章节增删（结构级），再标出条文增删（内容级）
3. **每条改动追问"为什么"**：删除项→推测原因（重复/无关联/层级不对）；新增项→识别为必须板块
4. **提炼为可迁移规则**：将具体改动抽象为"以后每次都这样做"的规则（如"三审三校必须独立成章""重点工作不超过5条""意识形态报告不带营收数据"）
5. **写入对应技能**：规则写入 skill 相应章节 + 更新检查清单
