基于 2019-2026 年实际文档分析（3726 份 docx/xlsx/pdf/txt/md，2.49GB）。涵盖四类核心文档。

## 一、月度工作报告

### 1.1 标题格式

| 类型 | 格式 | 示例 |
|------|------|------|
| 月度重点 | `紫金山事业部X月重点工作` | 紫金山事业部1月重点工作 |
| 工作计划 | `紫金山事业部X月份重点工作计划` | 紫金山事业部4月份重点工作计划 |
| 季度报告 | `紫金山事业部YYYY年X季度工作报告及X季度工作计划` | 紫金山事业部2026年一季度工作报告及二季度工作计划 |

### 1.2 写作规范

- **风格**：直接陈述，不铺垫不评论
- **每条结构**：`[项目名称] + [动作动词] + [具体行动] + [预期/进度]`
- **动词体系**：推进、完成、参与、落实、筹备、跟进、启动、敲定、延续
- **时态**：将来时/进行时（将、计划、继续、拟）
- **不写困难和不足**（另在专项汇报中写）
- **每条50-150字**，全文约800-1500字

### 1.3 分类体系（4月及以后用显式分类）

```
一、新媒体及活动业务     ← 一级标题（黑体16pt加粗）
二、旅游业务（或旅行社业务）
三、金融板块
```

### 1.4 典型句式

```
跟进包括'遇见宁'在内的25年完成执行的各项目回款工作，确保款项准时到位。
金融团队延续完成'谢谢不回家的你'和'马年窗花'两个春节项目，以及做好日常信息流广告发布工作。
推进'金陵非遗进华夏'活动落地执行，完成华夏银行合作视频拍摄等工作。
```

### 1.5 落款

```
紫金山事业部
2026年X月X日
```

## 二、意识形态报告

### 2.1 标题格式

| 类型 | 格式 |
|------|------|
| 月度研判 | `紫金山事业部X月意识形态（网络意识形态）领域情况分析研判报告` |
| 季度自查 | `紫金山事业部YYYY年X季度意识形态工作责任制落实情况自查报告` |
| 个人查摆 | `学习教育查摆问题清单` |

### 2.2 结构体系

**月度研判报告（三段式）**：

```
第一部分：X月开展的意识形态工作
├── 组织学习情况
├── 阵地管理情况
├── 重点工作审核把关情况（按项目逐一说明）
└── 工作成效总结

第二部分：发现的问题及整改措施
├── 如无问题 → 填写"无"
└── 如有问题 → 逐条列明问题+对应措施（一一对应）

第三部分：当前及下一阶段存在的风险隐患及应对措施
├── 风险点N：现象描述 + 危害分析 → 应对措施（一是……二是……三是……）
```

**季度自查报告（四段式）**：

```
一、X季度落实意识形态工作责任制整体情况
├── （一）从严落实主体责任
├── （二）从实推进重点工作（≤5条，按项目逐一说明）
└── （三）从细加强阵地管理

二、落实"三审三校"制度情况        ← 季度自查必须有此独立板块
├── （一）账号清单：自有账号X个 + 代运维账号X个，列到具体平台名
├── （二）发布流程：三审三校，代运营账号加相关处室四审后发布
└── （三）评论区管理标准

三、存在的问题及整改措施
├── 如无问题 → 填写"无"
└── 如有问题 → 逐条列明问题+对应措施

四、存在的风险隐患及应对措施
├── 风险点N：现象描述 + 危害分析 → 应对措施（一是……二是……三是……）
└── 末尾必须带：考核评分表 + 部门负责人签字
```

### 2.3 固定模板用语

**报告开头**：
```
现将X月意识形态领域情况及问题、风险隐患排查整治情况，
当前及下一阶段意识形态领域风险分析研判情况做如下汇报。
```

**风险应对措施**：
```
应对措施：一是加强……监测和研判能力……；二是……严格审核……从源头杜绝风险。
```

**工作回顾**：
```
部门在工作部署时，将意识形态工作纳入日常工作布局，与中心工作
一同规划、一同部署、一同落实。
重点活动审核把关：严格执行三审三校制度，对方案内容、传播素材进行双重审核，所有对外发布内容均严格把关，意识形态领域总体安全可控。
```

### 2.4 高频词

| 类别 | 词汇 |
|------|------|
| 阵地管理 | 内容、新媒体、审核、账号、平台 |
| 风险防控 | 风险、隐患、研判、应对、防控 |
| 行动措施 | 加强、落实、严格、确保、推进 |
| 组织责任 | 落实、部署、责任、领导 |

### 2.6 季度自查报告专项规则（基于2026年Q2报告定稿对比提炼）

以下6条规则适用于"意识形态工作责任制落实情况自查报告"类文稿，来自实际修改定稿过程。

**规则1：三审三校必须独立成章**
不能塞在"阵地管理"段落里一笔带过。季度自查报告必须有独立的"二、落实'三审三校'制度情况"板块，包含：
- 账号清单：精确到每个平台（自有几个、代运维几个，微信/微博分开列）
- 审核层级：自有账号"三审三校"，代运营账号"加上相关处室四审后发布"
- 评论区管理标准：政治立场→内容真实→表述准确，三条逐项列明

**规则2：重点工作不超过5条**
与意识形态直接关联弱的常规业务（如品牌活动策划、高校推广、康养旅游等）不写；内容重叠的项目合并（如"非遗美食活动"和"文化和自然遗产日"合并为一条）；宁愿少写不漏写。

**规则3：意识形态报告不带营收数据**
"截至X月底共计完成营收XXX万元"属于月度工作报告的素材，不应出现在意识形态自查报告中。

**规则4：每类信息只出现一次**
账号/审核类风险若已前置到"三审三校"板块详述，风险隐患部分就不再重复。避免同一信息在两个板块出现。

**规则5：代运营必须注明"四审"**
自有账号执行三审三校，代运营政务账号（如"南京文旅"）必须写明"加上相关处室四审后发布"——这是合规关键差异。

**规则6：末尾必须带考核评分表**
季度自查报告落款之后，必须附：
```
各部门意识形态暨网络意识形态工作考核评分表
部门负责人签字__________
```

### 2.7 落款

变体A：
```
紫金山事业部
2026年X月X日
部门负责人签字并盖章：
```

变体B：
```
报送单位：紫金山事业部
报送时间：2026年X月X日
部门负责人签字并盖章：
```

## 三、策划方案

### 3.1 标题格式

典型双行标题结构：
```
[品牌Slogan行]                ← 如"智享银龄 品质生活"
[完整方案名称行]              ← 如"2026南京银龄生活荟策划方案"
（讨论稿）                    ← 可选，居中、仿宋16pt
```

### 3.2 标准五段式框架

```
① 背景/缘起
   → 1-2段开篇引文：政策依据 + 现状描述 + 活动目的
   → 开篇无标题，直接以正文形式呈现
   
② 目标/定位
   → "活动定位与目标"章节，用（一）（二）（三）列举
   → 每条用四字短语概括：品牌长效化、非遗主题化、消费场景化

③ 内容/板块设计（全文核心，占60-70%篇幅）
   → 按（一）（二）（三）分板块，每个板块内分1.2.3.细项
   → 关键要素：时间、地点、活动形式、参与方式

④ 执行/排期/保障
   → 宣传推广、任务分工、新闻策划与传播

⑤ 预算/费用
   → 方案正文内通常不含预算表（预算另见于采购请示或独立成本文件）
   → 部分以"合作体系与招商"章节替代预算
```

### 3.3 标准章节模板

```
一、活动主题/品牌
二、活动时间
三、组织架构（指导单位 / 主办单位 / 承办单位）
四、活动规划（最大章节）
  （一）主板块活动
    1. 具体活动
    2. 具体活动
  （二）配套活动
    1. 线下配套
    2. 线上配套
  （三）主题展示（地铁/专列/街区等）
五、新闻策划与传播
  （一）权威新闻策划
  （二）融媒体互动产品
六、合作体系与招商
七、板块分工
```

### 3.4 开篇段句式

```
为贯彻/落实/进一步推动……，+ [主办方立足定位] + 特策划[活动名称]系列活动。

示例：
为贯彻习近平总书记对老龄工作作出的重要指示精神，落实积极应对人口老龄化国家战略，
南京报业传媒集团立足主流媒体职责使命，主动践行社会责任，特策划2026南京银龄生活荟系列活动。
```

### 3.5 语言特征

- **政策用语**：贯彻、落实、推动、促进、融合
- **四字短语**：品牌长效化、非遗主题化、消费场景化、全民参与化
- **并列结构**：一站式、沉浸式、高规格；有温度、有深度、有质感
- **动宾搭配**：打造IP、构建体系、形成氛围、实现转化
- **人称**：无第一人称，多用"拟""将""拟开展"

## 四、请示与报告

### 4.1 标准结构

```
标题：关于[主题]的请示               ← 最常用
主送：集团领导：                     ← 或"尊敬的领导："

正文：
  第一部分（缘由）：为……，按照……，现就……请示如下：
  第二部分（事项）：具体请示内容（分条列举）
  第三部分（结语）：当否/妥否，请批示。

落款：紫金山事业部
      2026年X月X日
```

### 4.2 结语选择

| 结语 | 语气 | 适用 |
|------|------|------|
| 当否，请批示。 | 标准 | 常规请示 |
| 当否，请批示！ | 稍强 | 紧急/重要事项 |
| 当否，请领导批示！ | 尊敬+强 | 需特别强调 |
| 妥否，请领导审示。 | 审慎 | 预算/资金类 |

### 4.3 附件格式

```
附件：1. XXXXXXXXXXXX
       2. XXXXXXXXXXXX
```

### 4.4 关键句式

```
【缘由】为加快推进……，按照……部署，……拟……
【事项】现就……请示如下：……
        （或：需……，用于……）
【资金】以上资金使用将严格执行……，专款专用……
【结语】当否，请领导批示。
```

## 五、工作总结

### 5.1 标准四段式结构

```
一、年度/季度经营情况概述
   → 开篇综述：营收数据 + 完成率 + 同比分析 + 整体评价
   → 关键句式："YYYY年，在……的领导下，……实现……"

二、主要工作/重点业务
   → 按业务板块平行展开（活动/旅游/金融/新媒体等）
   → 每个板块：营收数据 + 重点项目 + 亮点/突破
   → 格式：一级标题"一、二、三" + 正文直接陈述

三、存在的问题与不足
   → 宏观原因优先（经济下行/预算收缩/市场变化）
   → 再提内部原因（人员/能力/流程）
   → 典型写法："一是……二是……三是……"

四、下一年/下一季度工作计划
   → 目标 + 方向 + 重点突破
   → 语气：坚定、务实、有信心
```

### 5.2 数据呈现方式

- **优先嵌入正文**：文字叙述为主，数据散在段落中
- **固定模板表格**：考核评分表、绩效分配表
- **不用图表**：0% 使用图片/饼图/折线图
- **金额单位**：万元，保留2位小数
- **完成率**：百分数，保留2位小数（如84.93%）

### 5.3 典型用语

```
营收数据：全年完成营收XXXX万元，完成率XX.XX%
同比变化：同比+XX%（同比-XX%）
项目描述：全年共完成XX个项目，合同金额XX万元
问题表述：受经济下行/财政预算收紧/市场变化影响……
改进方向：下一步将重点在……方面加强/突破/深化
```

## 八、考核方案/制度类文档

### 8.1 核心原则

- **不出现具体人名**：只写岗位类别（编辑岗、撰稿岗、执行岗），不出现具体人员姓名。考核规则面向岗位和职责。

# MarkItDown — 文件转 Markdown 技能

## 简介

基于 Microsoft 开源的 [MarkItDown](https://github.com/microsoft/markitdown) 库（v0.1.5），将多种格式的文件统一转换为 Markdown，方便后续 AI 分析、知识库导入或二次编辑。

## 支持的格式

| 格式 | 说明 |
|------|------|
| `.txt` | 纯文本 |
| `.csv` | CSV 表格数据 |
| `.json` | JSON 数据 |
| `.xml` | XML 数据 |
| `.html` / `.htm` | HTML 网页 |
| `.docx` | Word 文档 |
| `.pptx` | PowerPoint 演示文稿 |
| `.xls` / `.xlsx` | Excel 表格（旧版+新版） |
| `.pdf` | PDF 文档 |
| `.jpg` / `.png` / `.gif` / `.webp` 等 | 图片（OCR 提取文字） |
| `.mp3` / `.wav` / `.m4a` 等 | 音频（语音转文字） |
| `.epub` | 电子书 |
| `.ipynb` | Jupyter Notebook |
| `.msg` | Outlook 邮件 |
| `.zip` | 压缩包（解压后逐个处理内部文件） |

## 用法

### 导入与初始化

```python
from markitdown import MarkItDown
md = MarkItDown()
```

### 转换本地文件

```python
result = md.convert("/path/to/文件.docx")
print(result.text_content)  # 获取 Markdown 文本
```

或使用更明确的 `convert_local`：

```python
result = md.convert_local("/path/to/文件.pdf")
markdown_text = result.text_content
```

### 转换网页 URL

```python
result = md.convert_url("https://example.com/article.html")
print(result.text_content)
```

### 批量转换目录下所有文件

```python
from pathlib import Path
from markitdown import MarkItDown

md = MarkItDown()
input_dir = Path("/mnt/e/百度云同步盘/工作台账/待处理")
output_dir = Path("/mnt/e/百度云同步盘/工作台账/Markdown输出")
output_dir.mkdir(exist_ok=True)

for f in input_dir.glob("*"):
    if f.suffix.lower() in ['.docx', '.pptx', '.xlsx', '.pdf', '.txt', '.csv']:
        result = md.convert(str(f))
        out_path = output_dir / f"{f.stem}.md"
        out_path.write_text(result.text_content, encoding='utf-8')
        print(f"✅ {f.name} → {out_path.name}")
```

## 🔄 批量处理健壮性

批量处理大量文件（如5000+工作台账扫描）时需注意：

```python
from markitdown import MarkItDown
from docx import Document  # 备用：python-docx
from pathlib import Path

md = MarkItDown()
input_dir = Path("/mnt/e/百度云同步盘/工作台账/")
success, fail = 0, 0

for f in sorted(input_dir.rglob("*")):
    # 跳过临时文件和非文档
    if f.name.startswith("~$") or f.suffix.lower() not in ['.docx','.xlsx','.pdf','.doc','.xls','.pptx','.txt']:
        continue
    try:
        if f.suffix.lower() in ('.doc', '.xls'):
            # 旧格式：python-docx/openpyxl 可能无法直接读取，尝试用markitdown
            result = md.convert(str(f))
        else:
            result = md.convert(str(f))
        text = result.text_content
        if text.strip():
            success += 1
        else:
            # 空内容 → 可能是扫描件或格式不支持，记录
            fail += 1
    except Exception as e:
        # 单个文件失败不中断批量处理
        fail += 1
        
print(f"✅ 成功: {success} | ❌ 失败: {fail}")
```

### 常见失败原因
- **`.doc`旧格式**：markitdown不支持，需先用LibreOffice转`.docx`
- **扫描件PDF**：使用`scripts/scan_pdf_ocr.py`逐页OCR
- **文件路径含特殊字符**：中文引号、空格等需用`glob`模式匹配
- **损坏的`.docx`**：提示"Package not found"或"File is not a zip"，用python-docx的`Document()`尝试读取
